# Архитектура системы

Дата: 14.11.2026. Статус: черновик для обсуждения и проверки командой.

Здесь описано, как будет устроен MVP: из каких частей состоит система, за что они отвечают, как обмениваются данными и где работают. Это план устройства системы, а не отчёт о готовых функциях. Внутреннее устройство 1С описано в [архитектуре подсистемы 1С](1c.md).

## 1. Назначение и граница системы

Система "Учебное расписание и конфликтология" помогает подготовить расписание, найти конфликты, согласовать результат и опубликовать его на сайте.

В систему входят приложение 1С, публичный фронтенд, бэкенд и хранилище опубликованного расписания PostgreSQL. Эти части обмениваются данными внутри системы. Интеграций с внешними информационными системами в MVP нет. Расписание и справочники пользователь загружает из CSV-файлов.

В MVP учебный отдел и администратор работают в 1С, посетители смотрят публичный сайт без входа. Рабочие кабинеты на сайте относятся к следующему этапу.

## 2. Пользователи

| Пользователь | Что делает |
|---|---|
| Учебный отдел (УО) | В 1С ведёт справочники, импортирует и редактирует занятия, работает с календарём, запускает проверки, разбирает конфликты, просматривает и экспортирует отчёт, передаёт расписание на согласование |
| Администратор расписания | В 1С рассматривает переданный снимок, согласовывает или отклоняет расписание с причиной, просматривает отчёт и журнал проверок; занятия не редактирует |
| Посетитель сайта | Без входа просматривает опубликованное расписание, выбирает неделю и фильтры по группе, преподавателю и аудитории |

Пользователи будут подключаться к 1С через браузер.

## 3. Состав системы

### 3.1. Приложение 1С

**Технология:** 1С:Предприятие 8.3.27.

В 1С работают УО и администратор расписания. Здесь хранятся справочники, занятия и расписания. Пользователи могут загружать и редактировать данные, проверять пересечения занятий и вместимость аудиторий, согласовывать расписание, просматривать и выгружать отчёты.

После одобрения 1С готовит публикацию из сохранённого снимка расписания и отправляет её бэкенду. Сохраняет результат доставки и позволяет повторить отправку той же версии.

Рабочие данные хранятся в информационной базе 1С.

### 3.2. Публичный фронтенд

**Технология:** HTML, CSS, JavaScript.

Загружается с сервера и выполняется в браузере посетителя. Показывает опубликованное расписание, позволяет выбрать неделю, группу, преподавателя и аудиторию. Отправляет выбранные параметры бэкенду и показывает полученные занятия. Списки групп, преподавателей и аудиторий для фильтров тоже получает от бэкенда.

Если расписание ещё не опубликовано, сообщает об этом. Если данные не удалось загрузить из-за ошибки, показывает отдельное сообщение.

### 3.3. Бэкенд

**Технология:** Python, FastAPI.

Принимает публикации от 1С через защищённый API и предоставляет публичный API для просмотра расписания. Проверяет служебный ключ, структуру и версию снимка, затем сохраняет публикацию в PostgreSQL. Проверка конфликтов и согласование остаются в 1С.

По запросу фронтенда выбирает занятия за нужную неделю с учётом группы, преподавателя и аудитории. Также возвращает списки значений для фильтров. Для просмотра расписания обращаться к 1С не нужно.

### 3.4. Хранилище опубликованного расписания

**Технология:** PostgreSQL.

Хранит последнюю успешно полученную публикацию: занятия, связанные с ними справочные данные, ID и номер публикации, время формирования и период.

Доступ к PostgreSQL имеет бэкенд. Браузер и 1С обращаются к бэкенду через API.

## 4. Связи между частями системы

Таблица показывает, кто к кому обращается, зачем и каким способом. Связь направлена от того, кто отправляет запрос, к тому, кто его принимает. Ответ API приходит в рамках того же запроса.

| Откуда | Куда | Что происходит | Способ связи |
|---|---|---|---|
| Учебный отдел | Приложение 1С | Готовит расписание, запускает проверки, работает с отчётами, передаёт на согласование | Веб-клиент 1С, HTTPS |
| Администратор расписания | Приложение 1С | Рассматривает, согласовывает или отклоняет расписание, просматривает отчёт и журнал | Веб-клиент 1С, HTTPS |
| Посетитель сайта | Публичный фронтенд | Просматривает расписание, выбирает неделю и фильтры | Интерфейс в браузере |
| Публичный фронтенд | Бэкенд | Запрашивает опубликованные занятия и значения фильтров | HTTPS, JSON API |
| Приложение 1С | Бэкенд | Передаёт полный снимок согласованного расписания, получает результат приёма | HTTPS, JSON API, служебный ключ |
| Бэкенд | Хранилище опубликованного расписания | Сохраняет публикацию, читает занятия, справочные данные и сведения о публикации | SQL, протокол PostgreSQL |

## 5. Публикация и публичный просмотр

1. УО готовит расписание в 1С и передаёт его на согласование. 1С сохраняет снимок проверенных данных, который затем рассматривает администратор.
2. Администратор одобряет расписание. 1С сохраняет решение вместе с подготовленной публикацией, затем начинает отправку.
3. 1С передаёт бэкенду полный снимок для публикации. Состав снимка описан ниже.
4. Бэкенд проверяет доступ, структуру и версию, сохраняет снимок в PostgreSQL и открывает новую версию для просмотра только после успешного сохранения.
5. Фронтенд запрашивает расписание и значения фильтров у бэкенда. Бэкенд читает опубликованную копию из PostgreSQL и возвращает подходящие занятия.

Снимок для публикации содержит:

- постоянный ID публикации, её возрастающий номер, время формирования и период;
- занятия: ID, дату, время начала и окончания, ссылки по ID на дисциплину, преподавателя, аудиторию и группы;
- ID и названия справочных записей, которые используются в этих занятиях.

Каждая публикация полностью заменяет прежнее расписание на сайте. Публиковать отдельные недели или заменять только часть периода нельзя.

На сайт передаются данные для просмотра расписания. Черновики, комментарии согласования, результаты проверок, численность групп и вместимость аудиторий на сайт не передаются. Поэтому снимок для сайта содержит меньше данных, чем снимок, который хранится в 1С для согласования.

## 6. Ошибки и защита обмена

- При повторной отправке ID, номер и содержимое публикации остаются прежними. Если бэкенд уже принял эту публикацию, он не применяет её повторно.
- Устаревшая версия не заменяет более новую. При ошибке приёма или сохранения предыдущая опубликованная копия остаётся доступной.
- Сбой доставки не отменяет согласование. Результат доставки учитывается отдельно; повторная отправка не требует нового согласования.
- Если 1С недоступна, сайт продолжает показывать сохранённое расписание. При отказе общего сервера недоступна вся система.
- До первой успешной публикации сайт сообщает, что расписание ещё не опубликовано. Это состояние отличается от ошибки загрузки данных.
- Для отправки публикаций используются HTTPS и служебный ключ. Секрет не хранится в Git и не передаётся браузеру.

## 7. План размещения

Планируется разместить 1С с веб-публикацией, FastAPI, PostgreSQL и файлы фронтенда на одном арендованном сервере:

| Адрес / доступ | Назначение |
|---|---|
| `/` основного домена | Файлы публичного фронтенда |
| `/api/` того же HTTPS-источника | Обратный прокси к FastAPI |
| Отдельный поддомен `1c.…` | Веб-доступ к 1С |
| Внутреннее подключение бэкенда | Доступ к PostgreSQL |

Сервер отдаёт файлы фронтенда, а браузер посетителя выполняет их. Бэкенд и PostgreSQL работают на сервере. У каждой части остаётся своя задача, даже если все они размещены на одном сервере.

## 8. Открытые вопросы

| Вопрос | Что нужно решить или проверить |
|---|---|
| Фронтенд | Будем ли использовать React |
| Работа с 1С | Выбрать режим информационной базы, проверить календарь, импорт и одновременную работу пользователей через браузер. Уточнить условия лицензирования удалённых подключений |
| Передача публикации | Определить поля и типы данных, смысл периода полного снимка, эндпоинты и ответы на ошибки, повторную отправку и устаревшую версию |
| API просмотра | Определить параметры недели и фильтров, формат занятий и справочных данных, ответ до первой публикации |
| Хранение публикации | Спроектировать таблицы PostgreSQL и замену расписания целиком: новая версия должна стать доступна только после полного сохранения |
| Размещение | Выбрать сервер, домен и веб-сервер, настроить HTTPS, хранение служебного ключа и доступ к сервисам |
