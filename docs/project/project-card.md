## 3. Бизнес-цель

Снизить конфликтность расписания (аудитория / группа / преподаватель) и сократить время его согласования.

**Целевой эффект:**
- число конфликтов на расписание не больше целевого порога (значение порога — уточнить);
- автоматическое выявление пересечений по аудитории, преподавателю и группе, в том числе для потоковых занятий;
- проверка ≥150 занятий быстрее 3 секунд;
- отчёт «Конфликты расписания» по типам, датам и преподавателям с экспортом в CSV;
- повторная загрузка CSV не создаёт дублей;
- сокращение времени согласования: статусы «Черновик → На согласовании → Опубликовано», отправка и публикация с комментариями;
- прозрачная динамика: журнал проверок показывает, как менялось число конфликтов.

## 6. Основные сущности (ERD v0.1)

- **audiences** — аудитории (audience_id, capacity).
- **teachers** — преподаватели (teacher_id, fio).
- **groups** — группы (group_id, size).
- **lessons** — занятия (lesson_id, teacher_id, audience_id, date, start_time, end_time, subject); группы в lessons не хранятся.
- **lesson_groups** — группы занятия (lesson_id, group_id): у обычного занятия одна строка, у потокового несколько.
- **time_slots** — сетка пар (номер пары, начало, конец), настраивается вузом.
- **conflicts** — найденные конфликты (type, date, time_range, participants, lessons[]).
- **schedules** — расписание со статусом (Черновик / На согласовании / Опубликовано).
- **users** — учётные записи и роли.
- **check_log** — журнал проверок (дата и время, автор, число занятий, число конфликтов, длительность).

Связи: audiences `1 — ∞` lessons; teachers `1 — ∞` lessons; lessons `1 — ∞` lesson_groups; groups `1 — ∞` lesson_groups (занятия и группы связаны `∞ — ∞` через lesson_groups); конфликт ссылается на занятия списком lessons[].

## 7. Границы MVP (MoSCoW)

Подробно: файл «11 Кейс — требования: цепочка и MoSCoW» (Must 47, Should 16, Could 6, Won't 8).

### Must have
- роли и права: учебный отдел, администратор, публичный просмотр без входа (Т-01–Т-03);
- вход по логину и паролю, тестовые пользователи (Т-04, Т-06, Т-09);
- импорт расписания из одного CSV; дубль в файле — ошибка; повторная загрузка заменяет черновик (Т-10, Т-11, Т-64);
- валидации при загрузке: время, рабочий день по сетке пар, ссылки, группы занятия; список ошибок с номером строки (Т-13–Т-20, Т-65);
- хранение групп занятия в `lesson_groups`, потоковые занятия (Т-21);
- поиск конфликтов типов 1–3 (аудитория, преподаватель, группа) с явным правилом пересечения и учётом потоков (Т-22–Т-25, Т-66);
- сохранение конфликтов с type, date, time_range, participants, lessons[]; запуск проверки кнопкой; пересчёт при повторной проверке (Т-27–Т-30);
- отчёт «Конфликты расписания»: поля, детализация по датам и преподавателям, сводные показатели, фильтры (Т-32–Т-36);
- экспорт отчёта в CSV (Т-37);
- согласование и публикация: статусы, отправка с комментарием, публикация или отказ, один черновик (Т-39, Т-40, Т-62, Т-63);
- экраны публичного просмотра и учебного отдела (Т-41, Т-42);
- проверка ≥150 занятий быстрее 3 секунд с замером в журнале (Т-45);
- журнал проверок (Т-50);
- синтетические данные, минимум 150 занятий (Т-54);
- данные и логика в 1С, публичный просмотр на сайте через API бэкенда (Т-56–Т-59).

### Should have
- учётные записи только через администратора, хэш пароля, вход один раз (Т-05, Т-07, Т-08);
- тип 4 (вместимость) по сумме групп занятия (Т-26);
- приоритет устранения конфликтов: аудитория → преподаватель → группа → вместимость (Т-31);
- метрики качества: конфликтность, плотность, стабильность (Т-38);
- экран администратора, пометка потоков в расписании (Т-43, Т-44);
- проверка не меняет данные и даёт повторяемый результат (Т-48, Т-49);
- журнал проверок: доступ ролей и динамика конфликтов (Т-52, Т-53);
- в тестовых данных потоки трёх видов: без конфликтов, с конфликтом по группе, с превышением вместимости (Т-55);
- вход и кабинеты на сайте (Т-60, Т-61);
- правка занятий черновика в системе (Т-69).

### Could have
- частичное обновление CSV по lesson_id (Т-12);
- совпадение времени занятия с парой сетки (Т-67);
- несколько сеток пар по дням недели (Т-68);
- запас по скорости: 1500 занятий, отчёт и фильтры до 3 секунд (Т-46, Т-47);
- запрет изменения и удаления записей журнала (Т-51).

### Won't have
- ограничение числа попыток входа, автоматический выход, смена пароля (W-01–W-03);
- интеграции с внешними системами: АСУ-расписания, BI (W-04);
- роль «Преподаватель» со входом, личным кабинетом и уведомлениями (W-05) — заменена публичным просмотром без входа;
- сетки пар по корпусам и по конкретным датам (W-06);
- 1С:Документооборот для согласования (W-07);
- 1С:Аналитика для дашбордов (W-08).
