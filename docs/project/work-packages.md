# Пакеты работ MVP

Кейс 11 «Учебное расписание и конфликтология». План от 16.11.2026.

## 1. Основа плана

Пакеты охватывают полный MVP по [архитектуре системы](../architecture/system.md) от 14.11.2026 и [архитектуре 1С](../architecture/1c.md) от 13.11.2026. Первые четыре соответствуют контейнерам C4. В сквозные работы входят общие тестовые данные, проверка всей системы и запуск на сервере.

Связанные требования указаны по ID из [реестра MoSCoW](../analysis/requirements_moscow.md).

## 3. Критерии готовности

### Приложение 1С

| Критерий готовности | Требования |
|---|---|
| УО ведёт справочники и загружает занятия. Может создать черновик или скопировать согласованное расписание, добавлять, менять и удалять занятия через формы. Календарь показывает занятия и позволяет открыть их для редактирования | Т-10, Т-21, Т-42, Т-64, Т-65, Т-69 |
| При импорте и ручном вводе действуют одни проверки данных. Ошибка в CSV оставляет прежний черновик без изменений | Т-11, Т-13–Т-20 |
| Система находит пересечения по аудитории, преподавателю и группам, а также превышение вместимости. Сохраняет результаты и записывает каждый запуск в журнал | Т-22–Т-30, Т-50, Т-66 |
| Отчёт показывает детали конфликтов и сводные показатели. Работают фильтры и выгрузка CSV | Т-32–Т-37 |
| Администратор рассматривает неизменный снимок, одобряет его или возвращает с причиной. Действия пользователей ограничены их правами и состоянием расписания | Т-01, Т-02, Т-04, Т-06, Т-09, Т-39, Т-40, Т-62, Т-63 с уточнениями архитектуры |
| После одобрения 1С создаёт и отправляет публикацию. При ошибке можно повторить отправку той же версии | Т-58 со стороны 1С |
| Приёмочные проверки пройдены на наборе 150+ занятий. Проверка расписания занимает меньше трёх секунд | Т-45; тестовые данные — Т-54 |

Рабочие данные и бизнес-логика хранятся и выполняются в 1С по Т-56.

### Бэкенд FastAPI

| Критерий готовности | Требования |
|---|---|
| Принимает снимок из 1С, проверяет служебный доступ, структуру и версию формата. При ошибке сохраняет текущую публикацию | Т-58 и архитектура |
| Повтор уже принятой публикации не меняет результат, старая версия не заменяет новую. Бэкенд подтверждает приём после полного сохранения | Т-58 совместно с PostgreSQL |
| Отдаёт опубликованные занятия за выбранную неделю и значения фильтров по группе, преподавателю и аудитории | Т-03, Т-41, Т-57, Т-59 совместно с сайтом |
| Отдаёт сохранённое расписание, даже если 1С недоступна. Черновики и внутренние данные согласования через публичный API недоступны | Т-03, Т-58, Т-59 |
| Возвращает разные ответы, если расписание ещё не опубликовано или произошла техническая ошибка | Архитектура системы |

Адреса запросов, поля и ответы опишем в API-контракте. Проверки занятий и поиск конфликтов остаются в 1С.

### PostgreSQL

| Критерий готовности | Требования |
|---|---|
| Миграции создают и обновляют структуру базы | Обеспечивает Т-58 |
| База хранит занятия, нужные справочные данные, ID и номер публикации | Т-41, Т-58 совместно с бэкендом |
| Новая публикация становится доступна целиком. Если сохранение прервалось, остаётся прежняя версия | Т-58 и архитектура |
| Бэкенд может выбрать расписание по неделе, группе, преподавателю и аудитории | Т-41 совместно с бэкендом |
| К базе подключается только бэкенд. Сайт и 1С работают через API | Т-59 и архитектура |

### Публичный сайт

| Критерий готовности | Требования |
|---|---|
| Посетитель без входа видит последнее опубликованное расписание. Черновики ему недоступны | Т-03, Т-57, Т-58 |
| Есть выбор недели и фильтры по группе, преподавателю и аудитории | Т-41; неделя — из архитектуры |
| Показывает дату, время, дисциплину, преподавателя, аудиторию и группы занятия | Обеспечивает просмотр по Т-41 |
| Потоковое занятие видно у каждой его группы, а у преподавателя — один раз со списком групп | Т-44, остаётся Should |
| Сайт показывает загрузку и отдельные сообщения, если публикации ещё нет, по фильтрам нет занятий или произошла ошибка | Архитектура системы; поведение интерфейса |
| Получает данные через API бэкенда | Т-59 |

Рабочие кабинеты УО и администратора запланированы на следующую версию.

### Сквозные работы

| Критерий готовности | Требования |
|---|---|
| Подготовлены синтетические CSV на 150+ занятий с ожидаемыми результатами. В наборе есть корректные данные, ошибки импорта, пересечения, потоки и превышение вместимости | Т-54, Т-55; требования импорта и конфликтов |
| Проверен весь путь: подготовка расписания в 1С → согласование → отправка → сохранение → просмотр на сайте | Т-39, Т-40, Т-58, Т-59 |
| Проверены сбой доставки, повторная отправка и попытка заменить новую версию старой. При ошибках сайт показывает прежнее расписание | Т-58 и архитектура |
| Все Must проверены, результаты записаны. Ошибки, мешающие их выполнению, исправлены и проверены повторно | Все Must через матрицу трассируемости |
| На наборе 150+ занятий проверка занимает меньше трёх секунд. Система записывает длительность в журнал | Т-45 |
| На сервере доступны 1С, сайт и API. Настроены HTTPS и служебный доступ, секреты хранятся вне Git | Архитектура размещения |
| Есть инструкции запуска и работы, тестовые учётные записи и сценарий демонстрации | Т-09 и обеспечение сдачи |
