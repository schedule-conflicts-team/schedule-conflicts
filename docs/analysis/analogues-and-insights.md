## 2. Список инсайтов

### 1. Объяснение конфликта должно помогать сразу перейти к исправлению

**Наблюдение:** в решении 1С ошибки сопровождаются описанием, а выбор ошибки выделяет связанные ячейки расписания.

**Вывод:** полезность проверки зависит от того, насколько быстро сотрудник понимает причину накладки и находит затронутые занятия.

**Решение для проекта:** показывать тип конфликта, общий ресурс, оба занятия и точный интервал пересечения; предусмотреть переход от строки отчёта к занятию.

**Основание:** [описание интерфейса 1С](https://solutions.1c.ru/catalog/asp_univer/features).

### 2. Повторная проверка после исправлений — самостоятельный важный сценарий

**Наблюдение:** аналоги предусматривают ручную корректировку; ТАНДЕМ также поддерживает разные версии, плановое и оперативное расписание.

**Вывод:** расписание меняется в процессе работы, поэтому результат проверки относится к конкретному состоянию данных.

**Решение для проекта:** организовать цикл «проверка → исправление (в MVP повторной загрузкой CSV) → повторная проверка», фиксировать время проверки и показывать изменение количества конфликтов.

**Основание:** [возможности модуля ТАНДЕМ](https://tandemservice.ru/products/tandem-university/moduli/osnovnye-moduli/raspisanie).

### 3. Допустимость расписания и его удобство нужно оценивать раздельно

**Наблюдение:** аналоги учитывают одновременно занятость ресурсов, предпочтения преподавателей, «окна» и удалённость зданий. В «Галактике РУЗ» предусмотрено ранжирование показателей качества.

**Вывод:** пересечение занятий и неудобное расположение занятий имеют разную значимость для учебного отдела.

**Решение для проекта:** в MVP выделить обязательные проверки: пересечения по аудитории, преподавателю и группе, а также вместимость аудитории. Показатели удобства развивать отдельно, сохраняя понятный приоритет ошибок.

**Основание:** [функциональные настройки «Галактики РУЗ»](https://galaktika.ru/ruz).

### 4. Проверка готового расписания может стать самостоятельной точкой входа в продукт

**Наблюдение:** ТАНДЕМ использует данные других модулей системы, а решение 1С поддерживает загрузку данных и обмен с вузовскими продуктами.

**Вывод:** для нашего проекта перспективна гипотеза, что учебному отделу будет полезно проверить существующее расписание через загрузку файла.

**Решение для проекта:** сделать основной сценарий коротким: импорт CSV → проверка → просмотр конфликтов → экспорт отчёта → отправка на согласование → публикация. Удобство такого сценария следует проверить с сотрудниками учебного отдела.

**Основания:** [взаимосвязи модулей ТАНДЕМ](https://tandemservice.ru/products/tandem-university/moduli/osnovnye-moduli/raspisanie) и [возможности обмена 1С](https://solutions.1c.ru/catalog/asp_univer/features).
