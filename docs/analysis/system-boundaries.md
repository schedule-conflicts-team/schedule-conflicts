# Границы системы

Кейс 11 «Учебное расписание и конфликтология».

| Граница | Внутри системы | За границей системы | Основание |
|---|---|---|---|
| **1. Функциональная** — что система делает | • загрузка расписания из CSV с проверкой корректности<br>• хранение и правка расписания<br>• поиск конфликтов 4 типов (аудитория, преподаватель, группа, вместимость)<br>• отчёт «Конфликты расписания»: сводные показатели, фильтры, экспорт в CSV<br>• журнал проверок<br>• согласование: отправка, согласование или отклонение с комментарием, публикация<br>• публичный просмотр опубликованного расписания на сайте с фильтрами по преподавателю, группе и аудитории<br>• учётные записи и роли | • автоматическое составление расписания<br>• автоматическое исправление конфликтов: система находит конфликты, исправляет человек (учебный отдел)<br>• публикация без подтверждения администратора<br>• ограничение попыток входа, автовыход, смена пароля | Кейс: «смоделируйте расписание и алгоритм выявления конфликтов»; Won't в MoSCoW |
| **2. Организационная** — кто пользуется системой | • учебный отдел (со входом): загрузка, проверка, исправление, отправка на согласование<br>• администратор расписания (со входом): согласование, учётные записи<br>• любой посетитель сайта, например студенты и преподаватели (без входа): только опубликованное расписание | • роль «Преподаватель» со входом, личным кабинетом и уведомлениями о конфликтах: заменена публичным просмотром<br>• самостоятельная регистрация: учётные записи создаёт только администратор | Кейс, разд. 2 п. 5 «Роли пользователей»; раздел «Авторизация и доступ»; решение команды (W-05) |
| **3. Граница данных** — что система знает | • аудитории (audience_id, capacity)<br>• преподаватели (teacher_id, fio)<br>• группы (group_id, size)<br>• занятия (lesson_id, teacher_id, audience_id, date, start_time, end_time, subject)<br>• группы занятий (lesson_groups)<br>• сетка пар (номер пары, время начала и конца)<br>• статус расписания и комментарии согласования<br>• учётные записи<br>• журнал проверок и найденные конфликты | • данные, которых нет в схеме (например, корпуса, учебные планы, нагрузка преподавателей): система их не учитывает<br>• реальные персональные данные: используются только синтетические | Кейс, раздел «Данные (синтетика; схема)»; ERD команды |
| **4. Граница с внешними системами** — с чем система связана | • 1С:Предприятие 8.3 (данные и логика), бэкенд с авторизацией, фронтенд — части одной системы<br>• на границе: обмен данными только через CSV (загрузка и экспорт) | • АСУ-расписания, BI-системы, API для сторонних систем: интеграций нет<br>• программы, в которых готовят CSV и открывают экспорт (например, Excel) | Кейс, разд. 5 «Требования к интеграции» и «Ограничения»; решение команды «логика в 1С» |
